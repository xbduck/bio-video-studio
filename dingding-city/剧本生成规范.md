# 剧本生成规范 · 叮叮城故事（企业文化专栏）

> **本文件是企业文化短剧剧本生成的最高约束。** `bio-video-studio` 网页「生成剧本」按钮会把这个规范的路径
> 一并放进提示词；WorkBuddy 生成剧本前必须先读 `角色圣经.md`（角色特征 + 视觉 DNA）和本文件。
> 两条都不读就动笔，必然跑偏（前 5 版血泪教训）。

---

## 0. 这是什么栏目

- **垂直类型**：企业文化短剧，虚构动物 IP，**不是生平短片**。没有 `year` / `age`，不写真实人物。
- **主角**：TT虎；**城市**：叮叮城；**规模**：共 **9 集**，对齐 T3 出行价值观表（3 大核心价值观 × 3 个行为关键词）。
- **画幅**：横屏 **16:9**（`aspect: landscape`），成片 1–3 分钟。
- **唯一事实来源**：`系列总览.md`（集数 ↔ 关键词 ↔ 价值观原文）、`角色圣经.md`（角色特征）、本规范（题材/结构/护栏）。

## 1. 确认班底（禁止新增常驻角色）

| 角色 | 身份（锁死） | 与主角关系 | 戏路 |
|------|--------------|------------|------|
| **TT虎** | 叮叮城运营中心**夜班值守 / 运营管家** | 主角 | 坐在调度台前盯运力大盘、派单、处置异常。**他不是司机，永远不出车接单**；白色小车只是他的通勤车 |
| **猫老板** | 城市运营负责人 | 搭档 / 灰色地带 | 抛业绩诱惑、下达团队决策；不是纯粹反派，是**规则视角** |
| **机器人小助手** | 轻盈飘浮的小机器人，手持平板，可投红光（警示）/ 绿光（合规） | 辅助 | 提醒与警示，不抢戏 |
| **兔妈妈** | 客服中心坐席（跨部门同事，EP.02 起） | 协同对象 | 当某集需要「部门协同 / 对方角度」的对手戏时**复用她**，不要新造一个同类角色 |

- **每集客串**的乘客 / 市民：一律用动物，从简，不立人设，不写名字。
- **铁律：叮叮城只有动物，没有人类。** 既破世界观，又与产线红线 `NO human hands` 冲突（早期 EP.02 出过人类女乘客，已废弃）。
- ❌ **禁止新造常驻角色**（如「小鹿」客服）——确需要跨部门同事时直接用**兔妈妈**。

## 2. 主题落点（每集必对齐价值观「对内」定义）

主题不是「对乘客好 / 服务态度」，而是**同事之间、部门之间的协同与选择**。从 `系列总览.md` 取本集关键词的**对内**定义：

| 集 | 关键词 | 对内落点（写剧本时对齐这句） |
|----|--------|------------------------------|
| EP.01 | 坚守底线 | 诚实正直，尊重他人，严格遵守规章制度与流程 |
| EP.02 | 说到做到 | 言出必行、行必果；在团队和部门协同中站在对方角度，从言行上完全支持团队决策 |
| EP.03 | 勇于担当 | 团队需要时敢于把后背交给伙伴，不计较个人得失，挺身而出担责 |
| EP.04 | 拥抱好奇 | 保持好奇、持续学习，主动推动日常改善与创新 |
| EP.05 | 创造价值 | 前瞻意识，遇困敢建新思路，做出差异与独特价值 |
| EP.06 | 能拿结果 | 认可文化，履责到位，不断拿到工作结果 |
| EP.07 | 协作赋能 | 利他思维，主动给予同事帮助，帮他人成长 |
| EP.08 | 平等开放 | 互相尊重平等，以同理心公平看待问题 |
| EP.09 | 共创共赢 | 顾全大局，正确处理局部与整体、短期与长远，以共赢贡献团队 |

> **致命坑**：把主题写成「老人等不到车、主角陪她」这类**对外服务**剧情，必然跑题。价值观的考场是**内部协同**。

## 3. 结构（8–12 镜，横屏 16:9）

- **标准弧**：暖承诺 / 日常 → 冲突 / 诱惑（低谷）→ 反转 ×1–3 → 回升 → 兑现 / 收尾点题。
- **跌宕起伏**靠 **2–3 次反转**，但反转必须来自**真实职场逻辑**（决策冲突、信息差、他人选择），不靠巧合或事故（如「全城掉线」是事故报告，不是故事）。
- **首镜**给情境，**末镜**收束到点题（可一句字幕，如「答应了，就办到；支持团队，也让团队更周全」）。

---

## 4. 逻辑护栏（v2–v6 反复踩坑，必守）

1. **零手动派单 / 转单**：转单是系统自动的。TT虎 只做真实运营动作——批量取消、加白名单、保活扩半径、台账记录。**不允许**写他逐个打电话协调司机。
2. **绝不让他开车接单 / 弃车 / 递伞**——那等于把他变成司机，与身份设定直接打架。
3. **张力不靠「乘客等太久」**：真实场景里等不到车会直接换平台。改用**公司侧主动动作**（批量取消、降级、关单、改派）作为矛盾源。
4. **不可出现「同一单既取消又送达」**：若取消与送达都要写，必须分属**不同司机 / 不同派遣**（两次 dispatch），让矛盾从根消失。
5. **旁白只描述画面真实存在的动作**；做不到的动作砍掉，或用姿态 / 拒绝承担。

## 5. 场景 schema（project.json 的 `scenes[]`，**无 year / age**）

```json
{
  "index": 1,
  "title": "第1镜 · 暴雨夜的值守台",
  "duration": 8,
  "narration": "深夜，暴雨红色预警。TT虎 守在运力大屏前，窗外的雨把整座城洗得发亮。",
  "sound": "暴雨拍窗、服务器风扇低鸣、告警提示音零星响起",
  "image_prompt": "<视觉DNA前缀> + 本镜画面主体/环境/光线",
  "video_prompt": "运镜：起幅→运动→落幅（图生视频务必加 Locked-off static camera, absolutely no camera movement, no zoom）",
  "image_path": "",
  "video_path": "",
  "audio_path": "",
  "image_status": "pending",
  "video_status": "pending"
}
```

- `narration`：**25–32 字 / 句**，数字写中文（「七十七亿」），不写英文缩写（Robotaxi / IPO 等 TTS 会读崩）。
- `image_prompt` / `video_prompt` **必带「视觉 DNA 前缀」**（见 `分镜模板.md` 第三节），否则全系列画风不统一。
- **视觉约束**：3D 卡通 Q 版、霓虹蓝橙雨夜叮叮城；`NO human hands` / `NO tail visible` / `nobody else enters`；`no readable text, no letters`；构图留脚（`full body visible with empty floor below, generous headroom`）。
- `duration` 合计落在 **1–3 分钟**（12 镜 × 8–14s 为宜）。

## 6. 落库方式

- 写 `projects/<项目>/script.json`（同上面的 `scenes[]` 结构）→
  `<PY> studio.py set-script <project_id> -f script.json` 自动落库并把 pending 的 script 任务标记 done。
- 或直接改 `project.json` 的 `scenes` 后，把 pending 的 script 任务标记 done。

## 7. 剧本自检清单（开集必过）

- [ ] 角色只用了确认班底 + 每集动物客串，**无新造常驻角色**
- [ ] 主题落在「内部协同 / 对方角度 / 完全支持团队决策」，**非对外服务态度**
- [ ] 含 2–3 次反转，且反转来自真实职场逻辑
- [ ] **无违例**：TT虎 开车 / 手动派单 / 同一单取消又送达 / 乘客苦等换平台
- [ ] 每镜 `image_prompt` / `video_prompt` 带视觉 DNA 前缀
- [ ] `scenes[]` 无 `year` / `age`，含 `sound` 字段
- [ ] 时长合计 1–3 分钟，画幅 `landscape`
- [ ] 旁白只描述画面真实存在的动作
